Trust nothing. Verify everything.

Security isn't a feature you add at the end — it's a property of every layer. Secrets in vaults, certs on every hop, least privilege by default, and an audit trail that can't be rewritten. The attacker only needs to be right once.

PRINCIPLE 01

Defence in depth.

No single layer stops everything. Edge, network, app, data — each assumes the one above is breached.

PRINCIPLE 02

Least privilege everywhere.

Every service, token, and role gets the minimum permissions it needs. Broad access is a future incident.

PRINCIPLE 03

Secrets are not config.

Passwords, keys, and tokens belong in a vault — never in env vars, repos, or config files.

PRINCIPLE 04

Log everything. Blame nothing.

An immutable audit trail is your best friend after a breach.

01

Defence in depth

CorePhilosophy
Difficulty

The story

Security is not a single wall — it's concentric rings. The edge (CDN, WAF, DDoS protection) filters volumetric attacks. The network (VPC, security groups, mTLS) ensures only authorised services talk. The application enforces auth, authz, and input validation. The data layer encrypts at rest with keys the app never holds. Each layer assumes the one above has been compromised.

▲ Use when
  • WAF + rate limiting at edge
  • VPC + security groups + mTLS between services
  • Input validation + AuthZ at every endpoint
▼ Avoid
  • Flat networks where any pod reaches any DB
  • "We have a firewall" as the whole strategy
  • Trusting traffic because "it's inside the VPC"
Connects to mTLS, DDoS, Zero trust
// Application-layer middleware stack — each is a ring of defence.
func main() {
    r := chi.NewRouter()
    r.Use(RateLimiter(100))           // ring 1: rate limit
    r.Use(RequestID)                  // ring 2: trace ID
    r.Use(AuthN)                       // ring 3: who are you?
    r.Use(AuthZ)                       // ring 4: are you allowed?
    r.Use(InputSanitize)              // ring 5: clean the input
    r.Use(AuditLog)                   // ring 6: log everything
    r.Mount("/v1", apiRouter())
}
# FastAPI — layered middleware = layered defence.
app.add_middleware(RateLimitMiddleware, rps=100)   # ring 1
app.add_middleware(RequestIDMiddleware)            # ring 2
app.add_middleware(AuthNMiddleware)               # ring 3
app.add_middleware(AuditLogMiddleware)            # ring 6

@app.post("/v1/orders")
async def create_order(
    body: OrderCreate,                              # ring 5
    user: User = Depends(require_role("buyer")),  # ring 4
): ...
// Spring Security filter chain = defence in depth.
@Bean
public SecurityFilterChain chain(HttpSecurity http) throws Exception {
    return http
        .addFilterBefore(rateLimiter, UsernamePasswordFilter.class)
        .csrf(Customizer.withDefaults())
        .oauth2ResourceServer(c -> c.jwt(Customizer.withDefaults()))
        .authorizeHttpRequests(a -> a
            .requestMatchers("/health").permitAll()
            .anyRequest().authenticated())
        .build();
}
02

Threat modelling (STRIDE)

CoreProcess
Difficulty

The story

STRIDE gives you six threat lenses. For every data flow in your system, ask: can the caller be spoofed? Can the message be tampered with? Can the action be denied? Can data leak? Can the service be crashed? Can someone escalate privilege? Do this at design review — not after deployment. Rank threats by impact × likelihood, then mitigate or explicitly accept.

▲ Use when
  • Run STRIDE at every design review for new services
  • Data-flow diagrams with trust boundaries marked
  • Rank threats: impact × likelihood → prioritise
▼ Avoid
  • Security review only after code is written
  • "We'll add security later"
  • Threat model once then never update
Connects to Defence in depth, Least privilege, AuthN
// Input validation — the "T" (Tampering) mitigation.
type CreateOrderReq struct {
    ProductID string  `json:"product_id" validate:"required,uuid"`
    Quantity  int     `json:"quantity"   validate:"required,min=1,max=100"`
}
var validate = validator.New()

func createOrder(w http.ResponseWriter, r *http.Request) {
    var req CreateOrderReq
    json.NewDecoder(r.Body).Decode(&req)
    if err := validate.Struct(req); err != nil {
        http.Error(w, err.Error(), 422); return
    }
    // Parameterised query — never string concat
    db.Exec(ctx, "INSERT INTO orders VALUES ($1,$2)", req.ProductID, req.Quantity)
}
# Pydantic = "T" (Tampering) defence in FastAPI.
from pydantic import BaseModel, Field
from uuid import UUID

class CreateOrder(BaseModel):
    product_id: UUID
    quantity: int = Field(ge=1, le=100)

@app.post("/v1/orders")
async def create(body: CreateOrder):
    await db.execute("INSERT INTO orders VALUES ($1,$2)",
        body.product_id, body.quantity)
// Jakarta Validation — Spring auto-validates @Valid.
public record CreateOrderReq(
    @NotNull UUID productId,
    @Min(1) @Max(100) int quantity
) {}
@PostMapping("/v1/orders")
public Order create(@Valid @RequestBody CreateOrderReq req) {
    return repo.save(new Order(req.productId(), req.quantity()));
}
03

Secrets management

CoreCritical
Difficulty

The story

Secrets must never live in code, config, or env vars baked into images. They belong in a secrets manager (Vault, AWS Secrets Manager). The app authenticates via IAM/K8s service account and fetches secrets dynamically. The gold standard: dynamic secrets — the vault generates short-lived DB credentials (1h TTL). If leaked, they expire before damage.

▲ Use when
  • Vault / Secrets Manager with IAM-based auth
  • Dynamic secrets with auto-rotation
  • Pre-commit hooks (gitleaks, truffleHog)
▼ Avoid
  • Secrets in .env, docker-compose, ConfigMaps
  • Shared long-lived API keys
  • Env vars for secrets — they leak into logs
Connects to Least privilege, Encryption, Audit logging
// Vault — fetch dynamic DB creds, auto-renew lease.
func dbCreds(v *vault.Client) (string, string, error) {
    secret, err := v.Logical().Read("database/creds/orders-svc")
    if err != nil { return "", "", err }
    user := secret.Data["username"].(string)
    pass := secret.Data["password"].(string)
    // Lease TTL = 1h. Renew in background goroutine.
    go v.NewLifetimeWatcher(&vault.LifetimeWatcherInput{Secret: secret})
    return user, pass, nil
}

04

Least privilege & IAM

CorePractical
Difficulty

The story

Every service, user, and token should have the minimum permissions required and nothing more. An orders-svc needs S3 read on its bucket, SQS send on its queue, and secrets read on its path — not *:* on everything. When that service gets compromised (and eventually, something will), the blast radius is bounded to its permissions.

▲ Use when
  • Per-service IAM roles scoped to exact resources
  • K8s RBAC: service accounts with minimal ClusterRole
  • DB: app user has SELECT/INSERT, not DROP/GRANT
▼ Avoid
  • Wildcard permissions: s3:*, iam:*
  • Shared admin credentials across services
  • Running apps as root / cluster-admin
Connects to Secrets, AuthZ, Zero trust
// Terraform — scoped IAM role for orders-svc.
resource "aws_iam_role_policy" "orders" {
  role = aws_iam_role.orders_svc.id
  policy = jsonencode({
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject"]
      Resource = "arn:aws:s3:::orders-bucket/orders-*"
    }, {
      Effect   = "Allow"
      Action   = ["sqs:SendMessage"]
      Resource = aws_sqs_queue.order_events.arn
    }]
  })
}
# AWS CDK — same policy, infrastructure-as-code.
orders_role = iam.Role(self, "OrdersSvc",
    assumed_by=iam.ServicePrincipal("ecs-tasks"))

bucket.grant_read(orders_role, "orders-*")  # only this prefix
queue.grant_send_messages(orders_role)     # only send, not receive
# Kubernetes RBAC — minimal service account.
# orders-svc can only read its own secrets.
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: orders-svc, namespace: prod }
rules:
  - apiGroups: [""]
    resources: ["secrets"]
    resourceNames: ["orders-db-creds"]
    verbs: ["get"]
05

mTLS & service identity

CoreNetwork
Difficulty

The story

Regular TLS proves the server is who it claims (the client verifies the server's cert). Mutual TLS adds the reverse: the server also verifies the client's cert. Both sides prove identity. This means a rogue pod that somehow lands in your VPC can't impersonate orders-svc — it doesn't have the cert. Service meshes (Istio, Linkerd) automate this entirely: inject a sidecar, auto-issue 24h certs, rotate silently.

▲ Use when
  • Service mesh (Istio/Linkerd) for automatic mTLS
  • SPIFFE/SPIRE for non-mesh workloads
  • Short-lived certs (24h) with auto-rotation
▼ Avoid
  • Long-lived manually-managed certs
  • Trusting IP-based identity inside the cluster
  • Disabling mTLS for "convenience" in staging
Connects to Defence in depth, Encryption, Zero trust
// Go — mTLS server: verify client certs.
caCert, _ := os.ReadFile("/certs/ca.pem")

06

Encryption at rest & in transit

CoreData
Difficulty

The story

In transit: TLS 1.3 for external traffic, mTLS for internal. No exceptions. At rest: transparent disk encryption (RDS/Aurora enable it in one click, S3 with SSE-KMS). For PII: add column-level encryption — even a DBA with DB access can't read raw SSNs/card numbers. Keys live in a KMS (AWS KMS, GCP Cloud KMS, Vault Transit) — the app calls KMS to encrypt/decrypt, never holds the master key.

▲ Use when
  • TLS 1.3 everywhere + mTLS between services
  • KMS-managed keys with automatic rotation
  • Column-level encryption for PII (SSN, card numbers)
▼ Avoid
  • Storing encryption keys alongside data
  • Rolling your own crypto — use KMS
  • "We encrypt at the app layer" without key rotation
Connects to Secrets, mTLS
// AWS KMS envelope encryption — encrypt PII column.
func encryptPII(ctx context.Context, kms *kms.Client, plaintext []byte) ([]byte, error) {
    out, err := kms.Encrypt(ctx, &kms.EncryptInput{
        KeyId:     aws.String("alias/pii-key"),
        Plaintext: plaintext,
    })
    return out.CiphertextBlob, err
}
# boto3 KMS — encrypt/decrypt PII.
import boto3

Supply-chain security & SBOM

CoreEmerging
Difficulty

The story

Your app might be 5,000 lines of code with 500 dependencies. Those dependencies have their own dependencies. A vulnerability in a transitive dep you've never heard of (like Log4Shell) can compromise your entire stack. SBOM (Software Bill of Materials) is a manifest of every component in your build — the first step to knowing what's at risk.

▲ Use when
  • Dependabot / Renovate for automated CVE patches
  • SBOM generation (syft, cyclonedx) in CI
  • Container image signing (cosign / Sigstore)
▼ Avoid
  • Unpinned deps: latest is not a version
  • Ignoring Dependabot PRs for months
  • No lockfile — non-reproducible builds
Connects to Secrets, Audit logging

Audit logging

CoreCompliance
Difficulty

The story

An audit log records who did what, when, and from where. It's append-only — no updates, no deletes. For tamper-evidence, each entry includes the hash of the previous entry (a hash chain). After a breach, the audit trail is your forensic timeline. Without it, you're guessing. Log every authentication event, privilege change, data access, and administrative action. Ship logs to an immutable store (S3 with Object Lock, CloudTrail, Loki) that even admins can't delete.

▲ Use when
  • Log every auth event, role change, data access
  • Append-only store (S3 Object Lock, WORM)
  • Alert on anomalous patterns (off-hours admin access)
▼ Avoid
  • Audit logs in a mutable database
  • Logging PII in plain text — hash or redact
  • No retention policy — logs fill up or get deleted
Connects to Structured logging, STRIDE (Repudiation)
// Append-only audit log with hash chain.
type AuditEntry struct {
    Seq      int64     `json:"seq"`
    Actor    string    `json:"actor"`
    Action   string    `json:"action"`
    Target   string    `json:"target"`
    IP       string    `json:"ip"`
    At       time.Time `json:"at"`
    PrevHash string    `json:"prev_hash"`
    Hash     string    `json:"hash"`
}

func (a *AuditLog) Append(entry AuditEntry) {
    entry.PrevHash = a.lastHash
    b, _ := json.Marshal(entry)
    entry.Hash = fmt.Sprintf("%x", sha256.Sum256(b))
    a.store.InsertOnly(entry)  // no UPDATE, no DELETE
    a.lastHash = entry.Hash
}

        json.dumps(entry, sort_keys=True).encode()).hexdigest()

Rate limiting & DDoS defence

CoreDefence
Difficulty

The story

DDoS defence is layered: the edge (Cloudflare, AWS Shield) absorbs volumetric L3/L4 floods. The WAF filters L7 attacks (SQL injection, bot traffic). The app does per-user/per-API-key rate limiting. Each layer absorbs a percentage of bad traffic so the layer below sees only a fraction. At the app layer, a token bucket or sliding window algorithm returns 429 Too Many Requests with a Retry-After header.

▲ Use when
  • Edge DDoS protection (Cloudflare, AWS Shield)
  • WAF rules for OWASP Top 10
  • Per-user token bucket at the app layer
▼ Avoid
  • Rate limiting only at the app — L3/L4 floods kill you first
  • Global rate limits that punish all users for one abuser
  • No Retry-After header — clients hammer harder
Connects to Rate limiting, Load shedding
// Token bucket rate limiter per API key.
import "golang.org/x/time/rate"

var limiters = make(map[string]*rate.Limiter)

func RateLimit(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        key := r.Header.Get("X-API-Key")
        lim := getOrCreate(key, rate.Limit(100), 20) // 100/s, burst 20
        if !lim.Allow() {
            w.Header().Set("Retry-After", "1")
            http.Error(w, "rate limited", 429); return
        }
        next.ServeHTTP(w, r)
    })
}

Zero trust

BonusArchitecture
Difficulty

The story

Zero trust means "never trust, always verify" — even for internal traffic. Every service-to-service call presents a cryptographic identity (mTLS cert or signed JWT). Every request is authorised against a policy engine. The network is assumed hostile. There is no "inside the perimeter." This is defence in depth taken to its logical conclusion: every component verifies every caller, every time.

In practice: service mesh (Istio/Linkerd) handles mTLS automatically. SPIFFE/SPIRE provides workload identity for non-mesh workloads. Policy engines (OPA/Rego, Cedar) make authorization decisions based on caller identity, not network location. The shift is cultural: stop trusting IPs, start trusting identities.

▲ Use when
  • mTLS everywhere via service mesh
  • SPIFFE workload identity for all services
  • OPA/Cedar policy engine for fine-grained AuthZ
▼ Avoid
  • IP-based allow-lists as the only access control
  • "It's internal, it doesn't need auth"
  • Skipping identity verification for "performance"
Connects to Defence in depth, mTLS, Least privilege
// OPA (Open Policy Agent) sidecar — every request checked.
func AuthZMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        input := map[string]interface{}{
            "caller":  r.TLS.PeerCertificates[0].Subject.CommonName,
            "method":  r.Method,
            "path":    r.URL.Path,
        }
        allowed, _ := opa.Eval(ctx, "data.authz.allow", input)
        if !allowed {
            http.Error(w, "forbidden", 403); return
        }
        next.ServeHTTP(w, r)
    })
}

// package authz
// allow { input.caller == "orders-svc"; input.path == "/v1/payments" }

// Spring + OPA sidecar — check policy on every request.

@Component
public class OpaAuthzFilter extends OncePerRequestFilter {
    private final RestClient opa = RestClient.create("http://localhost:8181");

    @Override
    protected void doFilterInternal(HttpServletRequest req,
                                    HttpServletResponse res,
                                    FilterChain chain) throws Exception {
        var input = Map.of(
            "caller", req.getUserPrincipal().getName(),
            "method", req.getMethod(),
            "path",   req.getRequestURI());
        var decision = opa.post()
            .uri("/v1/data/authz/allow")
            .body(Map.of("input", input))
            .retrieve().body(OpaResult.class);
        if (!decision.result()) {
            res.sendError(403); return;
        }
        chain.doFilter(req, res);
    }
}
