Principle 01

Theory pays rent.

You can't ship around CAP, isolation levels, or backpressure. The fundamentals show up in your incidents whether you read them or not.

Principle 02

Patterns > tools.

Tools change every three years. The pattern beneath them — saga, outbox, circuit breaker — has been the same for thirty.

Principle 03

Knowing when not to.

Senior engineers are valued for the architectures they refuse, not the ones they propose. Every concept here ends with "avoid when".

Principle 04

Boring code is real code.

Every concept ships with a short implementation in Go, Python (FastAPI) and Java (Spring Boot). Run it. Break it. Ship it.

How to read this

The pillars are ordered into four tiers, each building on the last. You can jump around, but the cross-references assume you've seen the foundations. One tier a month gives you a senior engineer's mental model in about a quarter. Cramming for an interview? Read tier one cover to cover, skim tier two, and pick from three and four by role.

Recommended reading

This guide teaches the breadth; these four teach the depth. If you read one, make it DDIA.

Must read

Designing Data-Intensive Applications

Martin Kleppmann

The single most recommended book for system design interviews. Replication, partitioning, consistency, batch vs stream — the theory behind every page here.

Covers: Pillars 01, 02, 05, 06
Deep dive

Database Internals

Alex Petrov

B-trees, LSM trees, WAL, MVCC, storage engine internals. When an interviewer asks “why Postgres over Cassandra”, this gives you the engine-level reasoning.

Covers: Pillar 02, in depth
Accessible

Understanding Distributed Systems

Roberto Vitillo

A gentler entry point than DDIA. Consensus, failure detection, replication — good for reinforcing pillar 01 before going deeper.

Covers: Pillar 01, reinforcement
Thinking

A Philosophy of Software Design

John Ousterhout

Not about systems — about complexity, abstractions and API surfaces. Deep modules, information hiding, tactical vs strategic programming.

Covers: Code design, senior thinking
